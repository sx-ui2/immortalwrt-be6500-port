# BE6500 v57 — 访问控制名单与无线频段识别修复

本版在已验证的 v56 内核、驱动及硬件配置基础上，更新访问控制名单逻辑与无线客户端频段识别。

## 本版修复

- 黑名单和白名单严格按照条目的添加顺序显示，不再按 MAC 地址重新排序。
- 旧名单默认采用“自动同步名称”模式；在线/已识别设备的最新名称会同步显示到名单。
- 从“选择设备添加”加入的条目持续跟随设备列表名称。
- 从“手动添加”加入的条目保存为手动名称，不会被后台自动覆盖。
- 每个名单条目增加“同步名称”“修改”“移除”：
  - “同步名称”恢复自动同步并立即采用设备列表中的名称；
  - “修改”允许为该 MAC 保存独立的手动名称；
  - 再次点击“同步名称”可取消手动名称。
- 名单保存时同时持久化名称模式，升级或重启后不会丢失。
- 修复 QSDK 主 MLD/hostapd 对象汇总客户端后，所有无线设备都被误报为连接 `2.4G` 的问题。
- 频段现在优先按照各个真实 hostapd BSS 控制接口中的关联终端判断；仅在控制接口没有该终端时才使用 ubus/iwinfo 兼容回退。
- 多链路终端会按真实关联情况显示 `2.4G / 5.2G / 5.8G` 中的一个或多个频段，普通单链路终端只显示所在频段。
- LuCI 页面包升级为 `luci-app-rejected-clients r49`。

## 刷写方法

在当前 ImmortalWrt 中打开 **系统 → 备份与升级**，上传：

`immortalwrt-qualcommax-ipq53xx-jdcloud_be6500_usb_native-squashfs-sysupgrade.bin`

- 不需要勾选“强制更新”。
- 可以按需要选择是否保留配置。
- 这是 sysupgrade 文件，不要上传到 uBootKit 的“固件更新”页面。

## 校验结果

- 沿用 v56 已验证内核，内核成员 SHA256 保持不变。
- sysupgrade BOARD 为 `jdcloud_be6500`，支持设备为 `jdcloud,be6500`。
- SquashFS 中控制器、页面脚本和样式与当前源码逐字节一致，频段识别回归用例已覆盖“主 2.4G 对象汇总全部终端”的情况。
- OpenWrt fwtool 元数据 CRC 已验证。
- 154 项 Python 回归测试及全部 5 项 Lua 行为测试通过。
